ADR-ID: 0003
TITLE: Mobile packaging via Capacitor (B2 step 20)
STATUS: Accepted, amended by ADR-0005
NOTE:
  ADR-0005 narrows the platform commitment this ADR assumed. Where this
  document refers to the roadmap as "Web/PWA -> Android -> iOS", read
  ADR-0005 instead: Android is the release target, the web build is the
  shared bundle rather than a separate release, and iOS is kept reachable
  but is not planned. Everything else here — the Capacitor decision, the
  committed `android/` project, the CI job — stands unchanged.
CONTEXT:
  ADR-0001 deferred Capacitor to "Stage 8" of the spec's own B2 staging and
  flagged this ADR for revisiting once that stage starts. The product
  roadmap (README) is Web/PWA -> Android -> iOS; this covers the Android
  half.
DECISION:
  - Capacitor (@capacitor/core, @capacitor/cli, @capacitor/android), all
    pinned to the same major (8.5.0) released together. Capacitor wraps the
    existing web build in a native WebView shell rather than requiring a
    second UI implementation, which matches this project's one-codebase
    approach (the same `dist/` output already serves web and PWA).
  - `capacitor.config.ts` sets `webDir: "dist"` and nothing else exotic —
    no native-only code path exists yet, so every platform (web, PWA,
    Android) runs the identical bundle.
  - `appId: "com.mergelab.app"` is a placeholder reverse-DNS identifier for
    local builds only. A real package id (one that will match an actual
    Play Console listing) is a product/business decision to make before
    any store submission, not something to invent here — changing it later
    is a one-line edit plus a `cap sync`, not a rewrite.
  - The generated `android/` project is committed, following Capacitor's
    own convention (it's the actual native project a developer opens in
    Android Studio and customizes — icons, permissions, splash screen —
    not a disposable build artifact). Its own `.gitignore` (generated by
    `cap add android`) excludes real build output (`build/`, `.gradle/`),
    the copied web assets (`app/src/main/assets/public`, regenerated by
    `cap sync` from `dist/`), and local machine config (`local.properties`).
  - CI gets a new `android` job that actually builds a debug APK
    (`./gradlew assembleDebug`) on GitHub's Ubuntu runners, which ship
    with an Android SDK preinstalled — this is real verification that the
    native project builds, not just that the scaffold exists. This was
    deliberately not something to fake locally: this project's own sandbox
    has no Android SDK, and its network policy blocks `dl.google.com`
    (Gradle itself downloads fine; resolving the Android Gradle Plugin from
    Google's Maven repo gets a 403 through this environment's proxy), so a
    local `./gradlew assembleDebug` fails at dependency resolution
    regardless of SDK. The CI job is the first environment that can
    actually attempt this build; on-device/emulator boot is still
    unverified anywhere and needs real hardware or Android Studio's
    emulator.
ALTERNATIVES:
  - React Native / Flutter (rewrite the UI in a different framework):
    rejected — the game is already a working Phaser/Canvas app; wrapping it
    is strictly less work and risk than a second UI implementation, and
    matches what the spec's own roadmap implies (ship the same web build).
  - Cordova instead of Capacitor: rejected — Capacitor is Ionic's actively
    maintained successor with a smaller, more current plugin API surface;
    Cordova is now mostly a compatibility layer Capacitor itself depends on
    for legacy plugins (`capacitor-cordova-android-plugins`, generated
    automatically and gitignored).
  - iOS platform in this same PR: deferred — the roadmap orders Android
    before iOS, and `@capacitor/ios` needs Xcode/macOS to build or verify
    at all, neither of which exists in this project's environments today.
    Adding it is additive (`cap add ios`) whenever that changes.
CONSEQUENCES:
  - `android/` is now part of the repo and needs the same review attention
    as any other checked-in code, even though most of it is
    Capacitor-generated scaffolding a developer wouldn't normally read line
    by line.
  - `pnpm cap:sync` (build + `cap sync`) must be run after any web change
    before testing on Android — this is a manual step for now; automating
    it further (e.g. a git hook) is not warranted at this stage.
  - Real device/emulator verification, code signing, and a Play Console
    listing are all still open — this ADR covers getting a debug build
    compiling, not shipping to a store.
MIGRATION:
  N/A — additive; no existing web/PWA behavior changes.
APPROVED_BY: alexd737@gmail.com
DATE: 2026-08-26
